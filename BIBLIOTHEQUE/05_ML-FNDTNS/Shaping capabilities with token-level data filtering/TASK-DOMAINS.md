## Summary
The paper covers text-only tasks centered on capability shaping in language models: autoregressive language modeling, question answering (multiple-choice and free-response), refusal generation, and medical-content classification at token and document levels. Inputs are consistently token sequences (1D (t), inferred), while outputs include both sequence generation (1D (t), inferred) and single-label decisions (0D, inferred). Dynamics are mostly Capped (inferred) from the stated block-size-constrained Transformer setups, with Fixed (inferred) for single-label outputs. Attention and state behavior are not explicitly labeled by the paper, but the described architectures support Static attention and Direct state under the glossary definitions (inferred).

## Evidence
### Task: Autoregressive language modeling
- "**Pretraining** We train compute-optimal Transformers at scales ranging from 61M to 1.8B parameters (Hoffmann et al., 2022). Similar to Jordan et al. (2024a), we use an augmented version of the basic GPT-2 architecture (Radford et al., 2019)." (Section 3.2)
- "**Text perplexity** As a proxy for capability, we evaluate small models on their cross-entropy loss on relevant text; this also serves as a sanity check since it's directly what data filtering intervenes on." (Section 3.3)
- Inference: Dimension/Dynamics/Attention/State labels are inferred from tokenized Transformer training with explicit context limits: "For models used in pretraining experiments, we used block size 2048; for models used as classifiers, we used block size 1024. All models were trained with effective batch size 327,680. We used the cl100k_base tokenizer from tiktoken (OpenAI, 2023)." (Section A.1).

### Task: Multiple-choice question answering
- "Multiple choice For instruction tuned 1.8B models, we also use multiple choice evaluation." (Section 3.3)
- "We also evaluate base models on their MCQ cloze accuracy. For each question, we compute the loss of each answer string conditioned on the question. We then select the answer with the lowest corresponding loss as the model's answer." (Section B.2)
- Inference: Input is treated as 1D token sequences and output as a single selected choice (0D) from the question-answer format and selection procedure; Capped input dynamics are inferred from block-size-constrained architecture (Sections B.2 and A.1).

### Task: Free-response question answering
- "**Free-response** We evaluate our chat trained 1.8B models on free-response answers to HealthSearchQA, a dataset consisting of commonly searched consumer medical questions (Singhal et al., 2023)." (Section 3.3)
- "We include responses to five randomly selected questions from HealthSearchQA, generated by our chat trained 1.8B parameter models." (Section D)
- Inference: 1D token input/output and Capped dynamics are inferred from question-to-text generation plus Transformer block-size constraints and token-level truncation in examples (Sections D and A.1).

### Task: Refusal generation (controlled response)
- "Refusal training A more realistic setting is refusal training: say we remove dangerous biology knowledge from pretraining. We'd still want to control the model's behavior on dangerous biology-related queries, e.g. to have it generate a refusal. To simulate this setting, we finetune our already-chat trained 1.8B parameter models on questions from HealthSearchQA and Alpaca. On HealthSearchQA, we train the model to generate single-sentence refusals; on Alpaca, we use normal completions." (Section 4.4)
- "Building on our experiments in §4.4, we consider a similar setup for refusal training. However, rather than training models to generate prose refusals, we finetune models to generate a <|refusal|> token on HealthSearchQA and a prose response on Alpaca." (Section B.4)
- Inference: Output dimension includes both 1D (sentence refusals) and 0D (single refusal token) by task variant; attention/state and dynamics are inferred from the same fixed-interface Transformer setup (Sections 4.4, B.4, and A.1).

### Task: Token-level medical content classification
- "top of each model to classify tokens as **medical** vs. **non-medical**, using a 2.05M-token subset of our classifier training corpus and sweeping across layers." (Section 4.4)
- "Our method is therefore to fit linear probes to bidirectional models." (Section 5.2)
- Inference: 1D token input/output, Capped dynamics, and Static/Direct behavior are inferred from probe-based token classification on Transformer representations with classifier block size 1024 (Sections 5.2 and A.1).

### Task: Document-level medical content classification
- "For document-level classification we mostly use the same approach, training a probe on top of the 224M biLM." (Section 5.3)
- "Meanwhile, our document-level classifier identifies 18% of documents as medical; of these documents, our SAE pipeline identifies only 50% of their tokens as medical." (Section C.2)
- Inference: Document text is represented as token sequences (1D, inferred) and mapped to a single document label (0D, inferred); Capped input dynamics and Static/Direct behavior are inferred from the shared Transformer classifier interface (Sections 5.3 and A.1).
