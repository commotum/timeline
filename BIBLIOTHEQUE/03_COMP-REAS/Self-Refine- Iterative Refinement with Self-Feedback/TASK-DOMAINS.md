## Summary
The paper explicitly evaluates seven generation tasks across natural language and code, and also reports a qualitative website generation use case beyond benchmarks. Inputs and outputs are primarily 1D (t) sequences (dialogue, reviews, titles, concept lists, code, and generated text/code), with website layout output also supporting a 2D (x, y) interpretation (inferred). Input dynamics are mostly not explicitly specified, except Constrained Generation where the input is explicitly capped at 20-30 concepts. Across tasks, the FEEDBACK-REFINE loop supports Dynamic attention and Constructed state (both inferred) through iterative, multi-aspect feedback and retained history.

## Evidence
### Task: Dialogue response generation
- "Open-domain dialogue response generation is a complex task that requires a system to generate human-like responses to a wide range of topics." (Section M Dialogue Response Generation)
- "The init module takes the dialogue context as input and generates a response that follows the conversation." (Section M.1 Modules)
- Inference: Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred from the global framework behavior: "To inform the model about the previous iterations, we retain the history of previous feedback and outputs by appending them to the prompt." (Section 2 Iterating Self-Refine)

### Task: Code optimization
- "Performance-Improving Code Edits or PIE (Madaan et al., 2023) focuses on enhancing the efficiency of functionally correct programs." (Section N Code Optimization)
- "The primary objective of PIE is to optimize a given program by implementing algorithmic modifications that lead to improved runtime performance." (Section N Code Optimization)
- Inference: Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred from iterative targeted feedback: "Given an optimization generated by PIE, SELF-REFINE first generates a natural language feedback on possible improvements... Then, the feedback is fed to REFINE..." (Section N Code Optimization), together with retained feedback/output history in Section 2.

### Task: Code readability improvement
- "In this section, we consider the problem of improving the readability of code with Self-Refine." (Section L Code Readability)
- "For our purpose, these are hard-to-read multi-line code snippets." (Section L.2 Experiments)
- Inference: Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred because feedback is generated and reapplied iteratively: "Starting from an initial piece of code y_0, we first critique... and then edit the code... This is recursively performed N times" (Section L.1 Method).

### Task: Math reasoning
- "We use the Grade School Math 8k (GSM-8k) dataset (Cobbe et al., 2021) for evaluating SELF-REFINE on math reasoning." (Section O Math Reasoning)
- "Following Gao et al. (2022), we write solutions to the reasoning problems in Python." (Section O Math Reasoning)
- Inference: Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred from iterative error-focused feedback: "FEEDBACK scans the solution to spot errors on which to provide feedback. The feedback is supplied to REFINE to create a new solution." (Section O Math Reasoning).

### Task: Sentiment reversal
- "We consider the task of long-form text style transfer, where given a passage (a few sentences) and an associated sentiment (positive or negative), the task is to re-write the passage to flip its sentiment (positive to negative or vice-versa)." (Section P Sentiment Reversal)
- "The iterations continue until the target sentiment is reached." (Section P Sentiment Reversal)
- Inference: Input includes both sequence text and a sentiment label (1D (t); 0D) from the explicit phrase "passage ... and an associated sentiment (positive or negative)"; Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred from iterative, pinpointed feedback: "the feedback not only indicates that the target sentiment has not reached, but further points out phrases and words in the review that should be altered" (Section P.1 Details).

### Task: Acronym generation
- "Acronym generation requires an iterative refinement process to create concise and memorable representations of complex terms or phrases" (Section K New Tasks)
- "Generate acronyms for a given title" (Table 4, Section A Evaluation Tasks)
- Inference: Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred from multi-criteria feedback and iterative scoring: "each acronym is judged along five dimensions" and "before generating the score ... we generate a reasoning chain explicitly" (Section Q Acronym Generation).

### Task: Constrained generation (CommonGen-Hard)
- "CommonGen-Hard requires models to generate coherent and grammatically correct sentences incorporating 20-30 concepts" (Section R Constrained Generation)
- "Constrained Generation, where the model is asked to generate a sentence containing up to 30 given concepts." (Section 3.3 Results)
- Inference: In Dynamics = Capped is supported by the explicit constraint "20-30 concepts"; Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred from iterative self-feedback on missing concepts and coherence in Sections R and S prompts.

### Task: Website generation (beyond benchmarks)
- "We explore this in a real-world use case of website generation, where the user provides a high-level goal and SELF-REFINE assists in iteratively developing the website." (Section 4 Analysis, Going Beyond Benchmarks)
- "Starting from a rudimentary initial design, SELF-REFINE refines HTML, CSS, and JS to evolve the website in terms of both usability and aesthetics." (Section 4 Analysis, Going Beyond Benchmarks)
- Inference: Out Dimension includes 2D (x, y) (inferred) because the paper frames this as "website layout generation" and shows iterative layout design updates in Section I Beyond Benchmarks; Attention Dynamic = Dynamic and State Dynamic = Constructed are inferred from iterative FEEDBACK-driven revision of layouts.
