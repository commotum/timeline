## 2. One-Sentence Contribution Summary

DynamicCity introduces "a novel 4D occupancy generation framework capable of generating large-scale, high-quality dynamic 4D scenes with semantics" to address dynamic urban scene generation (front matter).

## 6. Input and Representation Constraints

- Fixed 4D grid representation: "Given a 4D scene, i.e., a dynamic 3D occupancy sequence Q ∈ R^{T × X × Y × Z × C}" (Sec. 4 Our Approach).
- Fixed per-dataset resolution: "Each occupancy scene has a resolution of 200 × 200 × 16" and "The CarlaSC dataset [42] is a synthetic occupancy dataset, with a scene resolution of 128 × 128 × 8" (Sec. 5.1 Experimental Details).
- HexPlane representation uses exactly six 2D planes: "A dynamic 3D scene is represented as six 2D feature planes... H = [P_xy, P_xz, P_yz, P_tx, P_ty, P_tz]" (Sec. 3 Preliminaries).
- Latent compression and fixed downsampling: "Our latent HexPlane H is compressed to half the size of the input Q in each dimension" and "we select a downsampling rate of d_T = d_X = d_Y = d_Z = 2." (Sec. 5.1; Sec. 5.3)
- Patch size and tokenization: "we set the patch size p to 2" and "converting it into a sequence of N = ((X/d_X + Z/d_Z + T/d_T)/p)^2 tokens" (Sec. 7.3; Sec. 4.2).
- Padding constraints: "incorporating zero paddings in the uncovered corner areas" and "tokens corresponding to padding areas are excluded from the diffusion process." (Sec. 4.2)
- Condition alignment constraints: "The layout is padded to match the size of the HexPlane, ensuring that the positional encoding of the bird's-eye layout aligns with the XY plane." (Sec. 7.5)

## 7. Context Window and Attention Structure

- Maximum sequence length: "long sequential modeling (up to 128 frames)" (Fig. 1 caption, Sec. 1 Introduction).
- Sequence length fixed or variable: Variable; "The sequence lengths are 4, 8, 16, and 32, respectively." (Sec. 8.1)
- Attention type: Not specified; the paper describes a "transformer-based operation" in the Projection Module and a "DiT-based framework" for generation (Sec. 4.1; Sec. 4.2).
- Mechanisms to manage computational cost: "we employ the Padded Rollout Operation (PRO) to systematically arrange all six planes into a unified square feature map" and "tokens corresponding to padding areas are excluded from the diffusion process." (Sec. 4.2); "replace all attention mechanisms with FlashAttention [10] to accelerate training and reduce memory usage." (Sec. 7.3)

---

## 8. Positional Encoding (Critical Section)

- Positional encoding mechanism: Sinusoidal and frequency-based embeddings. The decoder uses "sinusoidal positional encoding" (Sec. 4.1), and the DiT uses "frequency-based positional embeddings" (Sec. 4.2).
- Where it is applied: VAE decoding uses "Concat(·) and PE(·) denote the concatenation and sinusoidal positional encoding" (Sec. 4.1); DiT applies PE after patchification: "we apply the frequency-based positional embeddings to all tokens" (Sec. 4.2). Conditional inputs also use PE: "we apply patch embedding and positional encoding operations to obtain condition tokens." (Sec. 7.5)
- Fixed across experiments vs modified: Not stated; no ablation or alternative PE comparison is described.

---

## 9. Positional Encoding as a Variable

- The paper treats positional encoding as a fixed architectural assumption; multiple PEs are not compared and no claim is made that PE choice is secondary. No explicit statements beyond the definitions above.

## 11. Architectural Workarounds

- Projection Module for compression: "DynamicCity employs a novel **Projection** Module to effectively compress 4D features into six 2D feature maps for HexPlane construction" (front matter).
- Parallel decoding: "we employ an **Expansion & Squeeze Strategy (ESS)**... to decode the HexPlane into multiple 3D feature volumes in parallel" (front matter; Sec. 4.1).
- Padded Rollout Operation with padding exclusion: "reorganize all six feature planes... as a squared 2D feature map" and "tokens corresponding to padding areas are excluded from the diffusion process." (front matter; Sec. 4.2)
- Patchification and fixed patch size: "converting it into a sequence of N = ... tokens, where p is the patch size" and "We set the patch size p to 2" (Sec. 4.2; Sec. 7.3).
- Efficiency-oriented attention: "replace all attention mechanisms with FlashAttention [10] to accelerate training and reduce memory usage." (Sec. 7.3)
- Condition branches: "we designed two branches for condition insertion... use the adaLN-Zero technique... add a cross-attention block" (Sec. 4.2)

## 12. Explicit Limitations and Non-Claims

- Latent size limits unconditional length: "Since our model is based on Latent Diffusion Models, it is inherently constrained to generate results that match the latent space dimensions, limiting the temporal length of unconditionally generated sequences." (Sec. 7.5)
- Long-sequence limitation: "our model's ability to generate extremely long sequences is still constrained by computational resources" (Sec. 10.3).
- Data coverage/generalization: "the generalization capability of DynamicCity depends on the diversity and representativeness of the training datasets." (Sec. 10.3)
- Complex traffic limitation: "it may face challenges in highly congested or intricate traffic environments" (Sec. 10.3).
- Semantic category limitation: "the reliance on pre-defined semantic categories means that any variations or new object types not included in the training set might be inadequately represented" (Sec. 10.3).

### 13. Constraint Profile (Synthesis)

> **Constraint Profile:**
> – Domain scope: Multiple datasets but same modality (voxelized 4D occupancy for driving scenes; real-world Waymo/nuScenes and synthetic CarlaSC).
> – Task structure: Multiple tasks (reconstruction, generation, conditional generation, forecasting) all within the same occupancy-domain setup.
> – Representation rigidity: Fixed 4D grid input, fixed HexPlane (six planes), fixed downsampling and patch size, explicit padding rules.
> – Model sharing vs specialization: Two-model pipeline (VAE + DiT), conditional branches for tasks, plus explicit fine-tuning for single-frame conditioning.
> – Role of positional encoding: Fixed sinusoidal/frequency-based PE applied to voxel features and tokens; not treated as a variable.

---

### 14. Final Classification

**Multi-task, single-domain.** The paper evaluates multiple tasks including "4D occupancy reconstruction," "4D scene generation," conditional generation variants (HexPlane/layout/command/trajectory/inpainting/outpainting), and "occupancy forecasting" (Secs. 4.1, 4.3, 5.2, 7.5, 8.2). All experiments use occupancy data from the same modality and domain family: "LiDAR point clouds have been completed and voxelized to form occupancy data" and a "synthetic occupancy dataset" (Sec. 5.1), so the evidence supports multi-task evaluation within a single domain rather than unrestrained multi-domain learning.
